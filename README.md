# Axum Server

Высокопроизводительный сервер на Rust (Axum) с модульной архитектурой, авто-документацией API и структурированным JSON-логированием.

## Предварительные требования

- **Rust** (последняя стабильная версия): `curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh`

## Структура проекта

```
src/
├── main.rs              # Точка входа: конфиг -> логирование -> БД -> роутер -> сервер
├── api/
│   ├── mod.rs           # AppState — общее состояние (БД + конфиг) для обработчиков
│   ├── router.rs        # Сборка роутера: маршруты, Swagger (dev), CORS, трассировка
│   ├── models.rs        # Единый формат ответов ApiResponse и helper'ы ok/internal_error
│   └── handlers/
│       └── basic.rs     # Эндпоинты: /, /test, /db
└── core/
    ├── config.rs        # Конфигурация: окружение (dev/prod), валидация переменных
    ├── db.rs            # Трейт Database + реализация на SQLite (sqlx)
    └── logging.rs       # JSON-логи с ротацией по датам: logs/YYYY/MM/DD/
```

Слои зависят только внутрь: `handlers` → `api::AppState` → `core`. Обработчики знают о БД через трейт `Database`, а не через конкретную реализацию — SQLite можно заменить на PostgreSQL, не трогая остальной код.

## Конфигурация

Конфигурация читается из переменных окружения, файлы `.env.*` подключаются как источник значений.

**Порядок приоритета**: системное окружение > `.env.{APP_ENV}` > `.env` (`dotenvy` не перезаписывает уже заданные переменные).

Создайте файлы конфигурации из шаблона:
```bash
cp .env.example .env.dev   # для разработки
cp .env.example .env       # для продакшена
```

| Переменная | Обязательна | Описание |
|---|---|---|
| `APP_ENV` | нет | `dev` (по умолчанию) или `prod`. Неизвестное значение — ошибка при старте |
| `DATABASE_URL` | да | Строка подключения к БД, напр. `sqlite:./sqlite.db` |
| `SERVER_HOST` | да | Адрес привязки: IP или имя хоста (`127.0.0.1`, `localhost`) |
| `SERVER_PORT` | да | Порт, число 0–65535 |
| `START_MESSAGE` | да | Приветственное сообщение при старте |
| `CORS_ALLOWED_ORIGINS` | нет | **Только prod**: разрешённые origin'ы через запятую. Пусто — CORS-заголовки не отдаются, чужие origin'ы блокируются браузером |
| `RUST_LOG` | нет | Переопределяет фильтр логирования (напр. `info,tower_http=warn`) |

## Запуск

### Разработка (по умолчанию, порт 8080)
```bash
cargo run
```

### Продакшен
```bash
APP_ENV=prod cargo run
```

При остановке по `Ctrl+C`/`SIGTERM` сервер дообрабатывает текущие запросы и завершается корректно (graceful shutdown).

## API и документация

| Эндпоинт | Описание |
|---|---|
| `GET /` | Базовая проверка сервера |
| `GET /test` | Тестовый эндпоинт |
| `GET /db` | Проверка подключения к БД (возвращает только успех/ошибку, без внутренних деталей) |

- **Swagger UI**: `/swagger-ui` — **только в dev-режиме**, в проде документация отключена
- **OpenAPI JSON**: `/swagger-ui/openapi.json`

Формат ответа единый:
```json
{ "status": "success", "message": "..." }
```
При серверных ошибках возвращается `500` и generic-сообщение, детали — только в логах.

## Логирование

JSON-логи с ротацией по датам: `logs/YYYY/MM/DD/`
- `info.json` — информационные события
- `debug.json` — подробные логи (в проде не пишется: фильтр `info`)
- `others.json` — предупреждения и ошибки

Файлы логов создаются с правами `600` (только владелец). Консоль: в dev — всё, в prod — только WARN/ERROR.
